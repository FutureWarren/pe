# OpenClaw 接入行动方案

面向：所里决策的人 + 负责动手配的人。

## 一句话

**OpenClaw 是又一只手。大脑（判断 / 话术 / 合规 / 评分 / 派单）已经建好了，
在律所服务器上，不动。** 这份方案要落的是：再接上几只手，并且保证一只手坏了
有人知道。

## 结论先放这

| 事 | 结论 |
|---|---|
| OpenClaw 是真的吗 | 是。开源自托管代理运行时，2025 年底发布，GitHub 38 万星以上 |
| 微信能接吗 | **能，而且腾讯官方维护插件**（`Tencent/openclaw-weixin`，扫码登录） |
| 美团 / 抖音能接吗 | **不能直接接。** 官方连接器里没有，要自己写浏览器自动化 |
| 装在律所服务器上吗 | **不。必须另一台机器。** 见「安全边界」 |
| 该先跑哪一段 | 美团后台**自动导出客资表**。零风险，一周出结论 |

## 我之前判断错的一处

我先前多次说「驱动微信有封号风险」，依据是个人账号使用规范禁止自动化。
**在 OpenClaw 这条路上这个判断站不住**：微信插件由腾讯自己维护并发布，
是官方连接，不是逆向。这一条更正掉。

**没有变的两条**（它们和封号无关，别一起划掉）：

1. **数据归属。** 若接的是个人微信号，当事人的案情就存在一个自然人的
   聊天记录里。律所既说不清处理链路，人走了也带不走。**企业微信客服那条线
   在这一点上是不可替代的**，不要因为多了 OpenClaw 就把它关掉。
2. **腾讯那个插件的文档里没有写速率限制、封禁策略、使用条款**——
   对一个大平台的官方集成来说这不太寻常。**先小规模跑，别一上来就铺满。**

## 安全边界（这一条不能省）

```
┌─────────────────────┐        ┌──────────────────────────┐
│  OpenClaw 那台机器   │  只有  │   律所服务器（现有）       │
│  · OpenClaw          │ 这一条 │   · 判断 / 话术 / 合规     │
│  · 微信插件          │ ─────▶ │   · 当事人咨询记录         │
│  · 桥接脚本          │  窄口  │   · 控制台                │
└─────────────────────┘        └──────────────────────────┘
```

**为什么必须分开两台：**

律所服务器上存着当事人的咨询记录——保密义务 + 个人信息保护法都盯着这块。
而 OpenClaw 是一个能自己写代码、装了几十个集成、会读取消息内容的代理运行时。
它读的内容来自陌生人（客户），这意味着**提示注入**是一个真实面：有人在美团上
发一段精心构造的话，试图让代理去干别的事。

把它和当事人数据放同一台机器，等于把这个风险直接架在最敏感的数据上。
分两台之后，最坏情况是那台机器被搞掉——重装即可，当事人数据一条都不在上面。

代价只是多一台机器。这个代价必须付。

## 需要准备的东西

| 项 | 说明 |
|---|---|
| 一台机器 | 常年开机。云主机（2 核 4G 起）或所里一台闲置电脑都行。**要能开图形界面**——后面做美团自动化必须有浏览器 |
| 一个微信号 | 专用，别用谁的私人号 |
| 渠道令牌 | 跟我要，会私信给你。**跟控制台登录令牌不是同一个** |
| 一个模型 API key | OpenClaw 自己也要调模型。**注意：我们的话术不用它的模型**，见下 |

### 关于「两个模型」这件事，别搞混

OpenClaw 自己会调一个模型（它本来是个通用助手）。**但对客户说什么，不能由它决定。**

所有对客户的话必须来自我们这边——那里有禁止事项闸门（不许报价、不许承诺结果、
不许预测判决）、有律所知识库、有留痕。OpenClaw 那侧的模型只用于它自己的
运行逻辑，**不许让它自由发挥回复客户**。

桥接脚本（`scripts/openclaw_bridge.py`）就是保证这一点的东西：消息进来先送到
我们这边，把我们给的话原样打回去。**它一个字的话术都不产生。**

## 分四步走，每步都有一个「继续还是打住」的判据

### 第一步：美团后台自动导出（本周，零风险）

让 OpenClaw 每天登录美团商家后台，把客资表下载下来，调控制台的导入接口。

不发消息、不加好友、不碰任何账号规则。

- **要花**：配置 2~4 小时
- **要证明的事**：这工具稳不稳、脚本好不好写、平台改版修起来费不费劲
- **继续的判据**：连着跑七天，每天都成功导入 → 继续。中间挂过两次以上 → 先解决稳定性，别往下走

这一步看起来最没意思，但它买到的是**你后面所有决策都需要的那个信息**：
这东西在你们手里到底稳不稳。

### 第二步：微信接上（第二周）

装腾讯那个微信插件，扫码登录专用号，桥接脚本连到我们大脑。

```bash
# 在 OpenClaw 那台机器上
export BRAIN_URL=http://<律所服务器地址>
export CHANNEL_TOKEN=<渠道令牌>
export CHANNEL=wechat
export CHANNEL_LABEL=微信-OpenClaw

python3 scripts/openclaw_bridge.py --probe        # 先自检
python3 scripts/openclaw_bridge.py                # 再跑起来
```

`--probe` 会告诉你三件事：大脑连不连得上、判断链通不通、发送地址对不对。
**三样不全绿就别往下走**，跑起来也是白跑。

然后把 OpenClaw 的消息 webhook 指到 `http://<这台机器>:8790/`。

- **先只挂一个号、只对一小批客户开**
- **继续的判据**：跑一周，首次响应时长中位数明显下降、且零合规事故 → 继续

### 第三步：美团 / 抖音自动回复（第三、四周）

到这一步才碰「自动回复」。账号是律所的商家账号，不是个人号，风险低一档。

要自己写浏览器自动化（官方连接器不覆盖）。桥接脚本不用改——
所有工具特有的东西都收在 `OpenClawAdapter` 一个类里。

### 第四步：铺开

到这时候加一个渠道应该是几天的事，不是几周。

## 成本

**先说一个大概率和直觉不一样的结论：AI 本身几乎不要钱。真正的成本是机器和人。**

| 项 | 量级 | 说明 |
|---|---|---|
| 律所服务器 | 已经在付 | 加渠道不用升配 |
| **AI 调用（DeepSeek）** | **一通完整对话约几分钱** | 每月 500 通 ≈ 几十块 |
| OpenClaw 软件 | 0 | 开源 |
| OpenClaw 自己的模型调用 | 视配置，可以很省 | 它只做运行逻辑，不产出话术 |
| **多一台常开机器** | 一次性两三千，或云主机每月几十到一百多 | **这是新增的硬成本** |
| 专用微信号 | ~0 | |
| **人：每天看一眼 + 平台改版时修脚本** | **这才是大头** | |

**关键性质：因为大脑只有一个，多接一只手不会让 AI 成本翻倍。**
加美团、加抖音、加小红书，AI 那部分还是几十块。**手越多，单位成本越低。**

真正随手数增长的是人力。粗估：一到两个渠道，每周半小时到一小时；
到五个渠道，基本要有人半天/周专门管。软件省不掉这一项，别指望。

## 产出怎么算

现成的真实数据是抖音后台那个漏斗：

**进私 416 → 开口 90（21.6%）→ 留资 50**

最刺眼的是：**416 个人点进来，326 个一句话没说就走了。**

这些人不是对法律问题没兴趣——点进私信是个有意图的动作。他们走，
主因是点进去一片空白、没人接话。**这一段正是 AI 补得最准的地方**，
因为它改变的不是说服力，是「这儿有没有人」这个最基本的判断。

```
增量线索 = 进私人数 × 开口率提升 × 留资率
增量收入 = 增量线索 × 签约率 × 客单价
```

保守假设开口率 21.6% → 30%、留资率维持 55%：每 416 个进私多出约 19 条留资线索。

**剩下三个数只有所里知道，填进去这笔账就闭合：**

- 留资线索的签约率
- 一单平均收入
- 每月进私总量（416 是一个月的量吗）

**另一块产出容易被漏掉，而且可能比上面更大：晚上和周末。**
人下班了，抖音和美团上的咨询不会下班，那部分现在是纯漏的。
AI 补的是这段真空，是纯增量，不抢任何人的活。

## 怎么判断「跑得好不好」

别用感觉，看两个数，控制台看板都有现成的：

1. **首次响应时长中位数**（北极星指标）
2. **留资率**

外加一条硬约束：**合规事故为零**。任何一次 AI 对客户提到钱、承诺结果、
预测判决，都算严重事故——立刻停，查出口闸门为什么没拦住。

## 一定会出事的地方，提前说

| 会出的事 | 已经有的兜底 |
|---|---|
| 那台机器停了、卡在更新弹窗上 | 心跳断了自动报警到管理员企微（`worker._sweep_channel_health`） |
| 回复发不出去堆在队列里 | 积压超时报警，同上 |
| 网络抖动导致消息丢失 | 发件箱 + ack 机制：没确认的一律重发，宁可重发不可丢 |
| 平台改版导致脚本失效 | 心跳会先报出来；脚本要修，这是常态成本 |
| 客户在消息里做提示注入 | 话术全部来自我们这侧，OpenClaw 不产出对客文本；且两台机器隔离 |
| 微信号被限制 | 先小规模跑；企业微信客服那条线**不要关**，它是不受影响的退路 |

## 现在就能做的

1. 找一台机器（云主机或闲置电脑，要能开图形界面）
2. 跟我要渠道令牌
3. 从第一步开始：美团后台自动导出

对接协议见 `docs/channels.md`，桥接脚本见 `scripts/openclaw_bridge.py`。
