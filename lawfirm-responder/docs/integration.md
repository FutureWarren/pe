# 企业微信接入方案

客户群已在企业微信上，因此不存在「个人微信 → 企微」的迁移问题。真正要解决的是两件事：

1. **读**：AI 怎么实时拿到客户群里的消息
2. **写**：AI 怎么以「销售顾问」身份在群里发言

两件事在企微的权限体系里是分开的，对应下面四条通道。系统四条都已支持，可组合使用。

**已实测结论（2026-07）**：自建应用回调**收不到客户群聊内容**（企微产品分层如此，只推
「发给应用」的单聊与事件）。因此群内自动旁听只有「@智能机器人」或「会话存档」两条路，
而**微信客服**是当前唯一免费且全自动（无需 @、无需员工操作）的进线通道。

---

## 通道对比

| | 读（收消息） | 写（发消息） | 前提条件 | 系统对接点 |
|---|---|---|---|---|
| **D. 微信客服** ⭐ | ✅ 客户每条消息自动推送，无需 @ | ✅ `kf/send_msg` | 免费；后台开通微信客服 + 客服 Secret | 读:`/wecom/callback` 的 `kf_msg_or_event` → `kf/sync_msg`；写:`gateway/wecom_kf.py` |
| **A. 群聊助手（@ 触发）** | 群内 **@智能机器人** 的消息 | ✅ 回调自带会话 webhook 直发 | 免费；后台创建智能机器人并拉入群 | 读:`/wecom/bot/callback`（独立 Token/AESKey）；写:`bot_webhook`（回落 `robot_webhook`） |
| **B. 会话存档** | ✅ 全量客户群消息（官方 SDK 拉取） | ❌ 本身不能发 | 服务版 900 元/人/年、5 人起购；群内告知存档 | 拉取器 → `POST /ingest` |
| **C. 影子模式 + 人工** | 同上任一 | 人（销售）复制粘贴 AI 草稿 | 无 | 控制台 `/console/replies` |

## 通道 D：微信客服（推荐首选，已实现）

**为什么是它**：客户从二维码/链接发起咨询，消息**全量自动**推送到我们的服务器，
客户不必 @、员工不必配置——这正是「第一道筛选」场景的天然形态。免费且是官方接口。

配置：
1. 企微后台 → **客户与上下游 → 微信客服** → 开通，创建客服账号（名称即 AI 对外身份）
2. 该页 **API** 处：填回调 URL（同 `/wecom/callback`，Token/AESKey 复用），复制**客服 Secret**
3. Secret 写入 `.env` 的 `RESPONDER_WECOM_KF_SECRET`（或部署命令带 `WECOM_KF_SECRET=xxx`）

客户入口：后台「微信客服 → 连接场景」可生成**链接与二维码**（官网/名片/朋友圈/公众号等），
客户扫码或点链接即进入咨询窗口，**无需添加好友**。

运行时行为：
- 回调只带 10 分钟有效的 `Token` → 系统据此调 `kf/sync_msg` 拉真实消息，`next_cursor` 持久化
  在 `kf_cursors` 表（重启不重复处理）
- 每个「客服账号 × 客户」自动建一份会话档案（默认**新咨询/prospect**，承办律师取
  `RESPONDER_KF_DEFAULT_LAWYER_NAME`），在控制台「群管理」里可直接编辑与开关 AI
- `origin=5`（真人接待发言）自动记为 staff → 触发人工接管静默；`origin=4`（系统推送）忽略

## 通道 A：群聊助手（@ 触发，已实现）

**适用场景**：已成交客户的服务群——客户与律师同在群里，助手只在被点名时出手，
不抢律师的话。客户零操作，员工只需建群时把机器人拉进来。

配置：
1. 企微后台 → 应用管理 → **智能机器人** → 创建（名称即对外身份，如「松沪助理」）
2. 在机器人的「接收消息」处填：URL `https://你的域名/wecom/bot/callback`，
   并记下它**独立的 Token / EncodingAESKey**（与应用的那套不同）
3. 写入 `.env` 的 `RESPONDER_WECOM_BOT_TOKEN` / `RESPONDER_WECOM_BOT_AES_KEY`
   （或部署命令带 `WECOM_BOT_TOKEN=xxx WECOM_BOT_AES_KEY=xxx`）
4. 把机器人加入试点群 —— **到此为止，无需任何按群配置**

**员工零配置的关键**：企微在每条机器人回调里下发一个该会话专用的 `WebhookUrl`，
系统据此自动建群档案并用它回复（`gateway/bot.py` → `worker._ensure_bot_profile`）。
所以新群不必人工登记、也不必再配群机器人；群会在下一条 @ 消息后自己出现在「群管理」里，
人工只需补上承办律师。该地址是分钟级短期有效的，过期（例如补位等待到点才发言）
自动回落到群档案里手工填的 `robot_webhook`；两者都没有时控制台自检会显式报警。

运行时行为：
- 正文先剥离开头的 `@昵称`（`gateway/mention.py`），否则「@点名→沉默」规则会误伤，
  且 @ 名字会污染模型上下文；句中出现的 @某某 属于对话内容，保留
- **群里机器人只收得到被 @ 的消息 → 一律零等待**（未被 @ 的消息根本不会推给我们；
  若日后接会话存档补读，那条通道的消息仍走原有补位等待，人工优先）
- 「@助手 在吗」不回「我帮您叫律师」——被叫的就是助手本人，直接应答
- 与机器人**单聊**（`ChatType=single`）同样受理，会话档案 ID 为 `bot:{userid}`
- 机器人被拉进群的事件先建档不说话，人工可提前配好承办律师
- 留联系方式同样进线索闭环，与客服通道共用一套简报与看板

## 筛查之后：分案与优先级

两条通道进来的咨询在筛查后汇入同一套分案系统：优先级评分（P0 强意愿/P1/P2，
规则见 `docs/lead-routing.md`）→ 按专长与负载自动派给具体律师 → 企微单聊推交接单 →
律师用个人账号进工作台跟进（只看自己的客户）→ P0 超时未联系自动督办。

## 推荐路线（按周推进）

**第 1 周 —— 通道 C（影子模式，当天可跑）**
读用任一可用方式（最低成本：销售把客户消息转给系统，或先用会话存档），AI 只出草稿进控制台，
销售看一眼、复制、以自己的身份发出。零 API 风险，同时积累真实样本校准判断引擎。

**第 2 周 —— 通道 A（机器人自动发言）**
1. 在试点群里添加群机器人（机器人的名字即 AI 的对外身份，如「顾问助理」——按业务决策不标注 AI）
2. 拿到机器人 webhook key，写入群档案 `robot_webhook`
3. 若企业具备智能机器人「接收消息回调」能力：在机器人配置里填回调 URL
   `https://你的域名/wecom/bot/callback`（注意与应用回调 `/wecom/callback` 不是同一个），
   把机器人**独立**的 Token / EncodingAESKey 写入 `.env` 的
   `RESPONDER_WECOM_BOT_TOKEN` / `RESPONDER_WECOM_BOT_AES_KEY`，系统自动完成 URL 验证
4. 切 `RESPONDER_MODE=live`，AI 开始自动发言；首周全量回复走控制台人工复核

**若机器人无法进入外部客户群 → 通道 B 补读**
购买会话存档许可 → 用官方 SDK 写一个拉取器（轮询增量消息），每条转成 JSON 打到
`POST /ingest`（带 `seconds_unanswered`，由拉取器根据消息时间计算）。
写仍走机器人 webhook；机器人也进不了群时，回落通道 C 半自动。

## 上线核对清单

- [ ] 企微管理后台创建自建应用（拿 corp_id / corp_secret / agent_id → `.env`）
- [ ] 服务器公网部署 `responder-api`，域名 + HTTPS（企微回调要求）
- [ ] 回调 URL 验证通过（系统已实现 GET echo）
- [ ] 试点群（劳动仲裁/法律纠纷）逐个建档：`PUT /console/groups/{id}`
      （客户状态、案件类型、承办律师 userid、第二责任人、robot_webhook）
- [ ] 律师单聊提醒试通（`message/send` 需应用可见范围包含承办律师）
- [ ] 影子模式跑 ≥ 1 周：分类准确率 ≥95%、草稿采纳率 ≥70%、零合规拦截误放
- [ ] 切 live，首周 100% 复核

## 身份与合规备注

按业务决策，AI 以普通销售顾问身份出现、不明示 AI。两点留意（不阻塞上线）：

- 《互联网信息服务深度合成管理规定》对 AI 生成内容有标识要求，客服/销售场景执法尺度尚宽，
  但建议保留随时可开的显式标识能力（改机器人昵称即可）。
- 系统对所有 AI 消息全量留痕（判断日志 + 回复记录 + 合规拦截记录），可溯源、可审计，
  这是不明示身份情况下最重要的兜底。

## 端到端验证方式

- **离线全链路**：`python -m pytest tests/e2e -q`
  —— 模拟企微加密回调（真实 AES + 签名）→ 判断 → 合规 → 机器人发送 → 提醒 → 接管 → 追问去重
- **对运行中服务回放**：`python scripts/e2e_replay.py --base-url http://127.0.0.1:8020`
  —— 把一段脱敏群聊逐条打进 `/ingest`，打印每条的判断与动作，最后汇总
- **接真实企微后**：在试点群里发测试消息，观察控制台 `/console/decisions` 与机器人回复
