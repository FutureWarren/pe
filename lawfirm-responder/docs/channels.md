# 外部渠道接入（给 RPA / 自动化工具的对接说明）

面向对象：负责配置影刀、龙虾这类自动化工具的人。**不需要懂我们的代码。**

## 一句话

你的工具只干两件事：**把客户说的话交进来**，**把我们给的话打回平台去**。
说什么、要不要说、什么能说，全在我们这一侧。

## 为什么这么分

多渠道最常见的死法，是每个渠道长出一套自己的话术和判断。三个月后同一个
「顾问」在五个平台上说话不像同一个人，改一句口径要改五个地方，漏一个就前后矛盾。
更要命的是合规：律所有一份禁止事项清单（不许报价、不许承诺结果、不许预测判决），
清单只挡得住经过我们出口的文字。

所以边界是硬的：**自动化工具里不许出现任何话术。** 一个字都不行。

好处是换工具的成本几乎为零——影刀换龙虾换别的，改的只是下面三个 HTTP 调用的
调用方，我们这侧一行不动。

## 准备

跟管理员要两样：

- 接口地址，形如 `http://<服务器地址>`
- **渠道令牌**（`RESPONDER_CHANNEL_TOKEN`）。跟控制台登录令牌**不是同一个**，
  别混用：自动化工具跑在一台随时可能被人碰的电脑上，令牌等于摊在那儿。

所有请求都带请求头 `X-Channel-Token: <渠道令牌>`。

再给这个渠道起一个**标识**（`channel`）：小写字母/数字/下划线/连字符，如
`meituan`、`dianping`、`meituan-jingan`。它会进数据库主键，所以别用中文和空格；
中文名放 `label`，那个是给人看的。

## 三个接口

### 1. 交一条客户消息

```
POST /channel/inbound
Content-Type: application/json
X-Channel-Token: <渠道令牌>

{
  "channel": "meituan",
  "external_id": "客户在该平台的稳定标识",
  "content": "公司拖欠我三个月工资，还把我辞退了",
  "msg_id": "平台侧消息ID（给不出可以不填）",
  "name": "客户昵称（可选）",
  "label": "美团-静安店（可选，给人看的渠道名）"
}
```

返回：

```json
{ "ok": true, "group_id": "ch:meituan:xxx",
  "replies": [ {"id": 12, "text": "您好，这边是上海松沪律师事务所…"} ] }
```

`replies` 就是**现在该对这个客户说的话**，按顺序发。可能是空数组——空数组
不是出错，是「这条不需要回」（客户只发了个表情、或者律师已经接手了，AI 该闭嘴）。

`external_id` 要**稳定**：同一个客户每次都得是同一个值，否则他每次来都被当成新人，
上次说过的话全白说了。平台的用户 ID 最好；只有昵称的话就用昵称，但昵称会改。

### 2. 取要说的话

```
GET /channel/outbox?channel=meituan&external_id=xxx
X-Channel-Token: <渠道令牌>
```

返回同上。用在两个地方：`inbound` 那次网络超时了；或者你想每隔几秒轮询一次
（有些回复是延后产生的，比如客户沉默一阵后的挽留）。

### 3. 报告发出去了

```
POST /channel/ack
{ "ids": [12, 13], "channel": "meituan" }
```

**这一步不能省。** 没 ack 的话下次还会取到——这是故意的：宁可重发一句，
不可丢一句。你 ack 之前，那句话一直算「还没送到客户眼前」。

### 4.（可选但强烈建议）报个到

```
POST /channel/heartbeat
{ "channel": "meituan", "label": "美团-静安店" }
```

没消息可交时也每隔几分钟调一次。

**为什么强烈建议**：你的脚本停了是**没有任何动静**的——系统弹个更新窗口、
浏览器改版、被人误关，它就不跑了。客户在那头等了三天，我们后台一片安静，
日志里连一行错误都没有。有心跳，超过设定时长没动静就会自动报警到管理员企业微信；
没心跳，「今天没客户」和「三天前就挂了」在数据上长得一模一样。

## 推荐的循环

```
每隔 3~5 秒：
    从平台上抓新消息
    对每条新消息：
        POST /channel/inbound
        把返回的 replies 按顺序打进平台的输入框
        POST /channel/ack（确认哪几条真发出去了）
    如果这一轮没有新消息：
        POST /channel/heartbeat
```

两条细节：

- **发完一条停 1~2 秒再发下一条。** 三条消息同一秒刷出来不像人。
- **发失败就别 ack。** 下一轮会再取到，比丢了强。

## 会自动发生的事（你不用管）

消息交进来之后，这些全部自动生效，和微信客服那条线一模一样：

- 判断该不该回、回什么（拿不准就沉默——AI 是补位，不是抢答）
- 禁止事项闸门：报价、承诺结果、预测判决、评价法官，一律拦下换成安全话术
- 全量留痕：每一条判断和回复都入库，控制台「AI 质检」页可查
- 线索评分与自动派单，强意愿的当场推给律师
- 客户记忆：他上次来说过什么，这次 AI 记得
- 律师接手后 AI 自动闭嘴，不抢话

## 常见返回码

| 码 | 含义 | 怎么办 |
|---|---|---|
| 401 | 令牌不对 | 检查 `X-Channel-Token` |
| 403 | 接入口没开，或没配渠道令牌 | 找管理员 |
| 400 | 渠道标识不合法 / `external_id` 为空 | 看上面的命名规则 |
| 5xx | 我们这边出问题了 | **别放弃这条消息**，隔几秒重试；重复交同一条 `msg_id` 是安全的 |

## 平台规则（这个不归代码管）

技术上能做，不等于平台允许做。开工前请自行确认目标平台当前的规则，
尤其是：**驱动个人微信号自动加好友、自动聊天，微信的个人账号使用规范是明文
禁止的**，且律所的客户关系和保密义务经不起一次封号。

安全得多的用法排序：

1. 只做**导出**——自动登录商家后台把客资表下载下来，导进控制台。不发消息、
   不加好友，风险极低。
2. 驱动**律所自己的商家后台**回复已有会话（美团、点评这类）。账号是律所的，
   也不是主动加人。
3. 驱动**个人微信号**主动加人聊案情。不建议；真要做，也请只做「引导客户扫码
   进正式咨询窗口」这一件事，案情一律在企业微信里聊。
