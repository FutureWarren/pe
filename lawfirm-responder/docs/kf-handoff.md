# 会话转接：不搬信息，搬客户

## 要解决的问题

现在的交接链路，最后一步是最脆的：

```
AI 跟客户聊 → 整理交接单 → 推给律师 → 律师打电话 → ❌ 客户没接
```

陌生号码接通率本来就低，何况我们的客户往往正在上班、开庭、或者正因为
被辞退而不敢接不认识的电话。前面攒的全部上下文，在「挂断」那一刻归零。

**会话转接换一个模型：AI 是前台，聊到该人接手时把人领进来，而不是把笔记递出去。**

```
AI 跟客户聊 → 判定值得人工接手 → 把会话转给律师 → 律师在原窗口接着聊
```

- **客户**：没有切换感，还是那个窗口，只是回话的人变了，不用等电话
- **律师**：打开企微就看到完整聊天记录，不用读交接单、不用自我介绍
- **我们**：「搬运」这个环节直接消失

## 机制

微信客服的会话有状态机，`kf/service_state/trans` 可以改：

| 状态 | 含义 | 我们的用法 |
|---|---|---|
| 0 | 未处理 | 新会话 |
| 1 | 由智能助手接待 | **AI 工作时的常态** |
| 2 | 待接入池 | 不用 |
| 3 | 由人工接待 | **转接目标**，需指定 `servicer_userid` |
| 4 | 已结束 | 会话收尾 |

转成 3 并指定律师的 userid，这通会话就出现在那位律师企业微信的客服工作台里，
历史消息齐全，他直接回就行。

> ⚠️ 接口名与字段以企微文档为准。开发环境访问不到 developer.work.weixin.qq.com
> （出网 403），故先跑 `scripts/kf_probe.py` 拿真实返回确认，再落地代码。

## 什么时候转（最关键的决策）

**转早了律所会被淹**：一周 416 人进私信，全转过去律师什么也别干了。
**转晚了就失去了那个当口**。

**判据是一张清单，不是分数**（律所方 2026-08-09 拍板，`priority.WANTS_HUMAN`）：

| 客户做了什么 | 动作 |
|---|---|
| **紧急**（拘留 / 传唤 / 开庭临近 / 情绪崩溃） | **立刻转**，他还没开口要人，但等他开口就晚了 |
| 说要委托 / 要找律师 | **转** |
| 想来所里面谈 | **转** |
| 要律师直接联系他 | **转** |
| 有人受伤 / 住院 | **转** |
| 要加微信详聊 | **转** |
| 留了电话 | **转** |
| 只是问法律问题 / 只问收费 / 只打招呼 | 不转。AI 接着摸情况，那正是它的活 |

原来这里挂的是「P0（≥60 分）才转」。**那是把两个问题绑在了一起**：
分数回答的是「十个人同时进来先给谁打电话」——排队问题，需要排序；
「现在要不要把真人叫过来」只需要知道客户是不是已经在要真人了。
绑在一起的后果，律所方在真机里撞见了：客户明明说了「让律师给我打电话」，
系统还在算他够不够 60 分，于是判成弱意愿、不转。

那道门槛当初是怕转太多（一周 416 人进私信）。**这个顾虑现在不成立了**：
转过去 90 秒没人接手，AI 自动接着陪（`handoff_grace_seconds`，且不清转接状态，
律师随时能接手）。转多了的代价只是企微里多几个待接窗口，不再是客户被晾着——
代价变了，规则就该跟着变。

按现有漏斗估算：留资约 50 人/周 ≈ **7 单/天**分摊到全所，量是合适的。
清单里刻意不含 `fee`（只问收费）、`depth`（聊得久）、`amount`（金额大）、
`deadline`（有时限）——它们说明**案子值钱**，不说明**客户想找人**。

转给谁不用另做逻辑 —— `assignment.ensure()` 已经按专长与负载算出来了，
转接只是把那个决定**兑现**。

## 转接前要先跟客户说一句

直接转会出现一段尴尬的静默（律师还没看到）。所以顺序是：

1. AI 先发一句过渡话术
2. 再调 `service_state/trans`

```
您的情况我整理好，转给我们的律师了，稍等一下就在这个对话里回您。
您要是还有材料（合同、聊天记录、工资条），可以先发过来。
```

> **不点名**（业务决策 2026-08，见 CLAUDE.md 对客称呼一条）。曾经考虑过点名——
> 转接这一刻人已经定了，说出来是准的。但律所方的判断更稳：客户读到名字就会等
> 那个人，而律师可能临时改派、可能没接手，等的就成了一个不会出现的人。
> 「有个具体的人接手了」这份分量靠**律师真的开口**来给，不靠一个名字。
>
> 末句给一个此刻就能做的事。转接不是终点——客户手上闲着的这段等待期最容易走神，
> 让他去翻合同、找工资条，既填住了等待，材料也真的有用。

## 转接之后

**AI 必须闭嘴。** 现有的「人工接管」静默是靠律师**发言**触发的
（`gate:human-takeover`），但转接发生在律师说话之前，所以需要一个显式状态：

- `groups.handoff_userid` / `handoff_at` → 判断层新增 `gate:handed-off`，AI 一律沉默
- 律师在企微里回话 → 照常，AI 保持沉默
- 会话结束 → 清状态

## 新增的失败模式（必须兜住）

转接不是成功的保证，它引入了一个**比现状更糟**的可能：
客户被交给一个不看企业微信的律师，晾在那儿没人理 —— 那还不如 AI 一直陪着。

三层兜底：

1. **转接后 SLA**：转接后客户又发了消息、而律师 N 分钟内没回
   → 提醒律师，再超时抄送第二责任人（复用 `notify/escalation.py` 的升级链）
2. **兜底回收**：超时未接手可以把状态转回 1（智能助手接待），AI 重新接上，
   至少客户不是对着空气说话
3. **转接失败即回落**：`trans` 调用失败一律回落到现有链路
   （交接单 DM + 电话），绝不让客户悬着

## 最容易踩的坑

**律师必须是该客服账号的「接待人」**，否则 `trans` 直接失败。

律师名册的 userid 集合 ⊆ 客服账号接待人列表 —— 这个约束现在没人校验，
而它失败的时机恰恰是最要紧的那一刻（P0 线索来了）。因此：

- `/console/kf/handoff-probe`（控制台「状态」页按钮「检查转接是否就绪」）报三件事：
  **名册与接待人列表的差集**（缺谁点名报出来）、开关与运行模式、以及
  **拿一通真实会话读一次 `service_state`**——只读不改，用来验证接口路径配得对。
  做成网页按钮而不是命令行脚本，是因为企微 API 限可信 IP、只有服务器调得通，
  而律所侧没有 SSH。
- 转接前再校验一次接待人，不在列表里的直接走回落链路，不做无谓的调用，
  **也不会先跟客户说「转给律师了」**——那句话发出去客户就真的在等了。

## 抖音那边

没有对等能力，也不需要 —— 抖音侧接待走 AI即用，它自带转人工
（负向情绪识别 / 关键词二次命中 / 命中转人工知识，见 `docs/douyin-ai-setup.md`）。
本方案是**微信客服专属**。

## 落地顺序

| 阶段 | 内容 | 状态 |
|---|---|---|
| 1 | 会话状态字段 + `gate:handed-off` 静默 | ✅ 已完成 |
| 2 | `wecom_kf.service_state / transfer` | ✅ 已完成（路径走配置项，见下） |
| 3 | 触发条件 + 过渡话术 + 回落 | ✅ 已完成（`service._maybe_handoff`） |
| 4 | 转接后 SLA 与兜底回收 | 回收已做（`handoff_reclaim_seconds`）；SLA 升级待做 |
| 5 | 控制台：接待人差集自检 ✅、转接状态展示、转接后首响时长 | 部分完成 |

接口路径没等探测就先写了代码——企微文档站在开发环境不可达（出网 403），
硬等下去这功能永远上不了线。所以路径做成配置项 `RESPONDER_KF_TRANS_PATH` /
`RESPONDER_KF_STATE_PATH`，部署后在控制台点一次自检，探到路径不对**改环境变量即可，
不必改代码重新部署**。这是抖音发送 endpoint 用过的同一套办法。

## 上线前的两件人工事项（少一件转接就是废的）

1. **把律师加成接待人**：控制台「状态」页 → **「把名册律师加为接待人」**，一个按钮。
   服务器直接调 `kf/servicer/add`，加完立刻回读列表确认。
   > ⚠️ **不要去 kf.weixin.qq.com 手工点**。这个客服账号由企微应用托管，那个后台
   > 顶部横幅写着「正在通过企业微信应用管理相关能力，启用后将由此处统一接管
   > 用户咨询和客服账号」——点了那个「开始使用」，管理权会被夺回网页侧，
   > 消息推送会断，整套 AI 当场哑掉。既然程序有权限，就让程序加。
2. **点一次控制台的「检查转接是否就绪」**，看到「接待人齐、接口通」才算真的能用。

## 说到底这是个组织问题，不只是技术问题

转接能不能成，取决于**律师是否真的会看企业微信的客服工作台**。
技术上把客户送到门口很容易，人不开门就没用。

所以上线前建议先小范围试：**指定一两位律师做接待人**，跑一周看首响时长，
再决定要不要全所铺开。数据在控制台看板上（阶段 5）。
